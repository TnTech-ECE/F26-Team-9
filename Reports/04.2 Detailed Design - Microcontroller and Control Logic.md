## General Requirements for the Document

The objectives of this subsystem are to:

1. Implement the pump control algorithm using the STM32 Nucleo-L476RG microcontroller.
2. Receive flow rate, inlet temperature, outlet temperature, and representative heating demand inputs.
3. Provide documented electrical connections between the microcontroller and the other hardware subsystems.
4. Identify the STM32 pins, peripheral functions, power inputs, and signal conditioning requirements.
5. Calculate pump speed commands using flow, heating demand, and outlet temperature feedback.
6. Enforce the selected pump speed, minimum flow, and temperature operating limits.
7. Detect invalid measurements and execute approved fault handling procedures.
8. Support baseline and controlled operation during physical bench testing.
9. Transmit operating measurements, controller states, pump commands, and fault codes to the Data Logging and Simulation Subsystem.
10. Verify the controller hardware, firmware, and electrical interfaces before integration with the physical bench.

## Function of the Subsystem

The Microcontroller and Control Logic Subsystem is responsible for processing operating measurements and controlling the speed of the circulation pump. The proposed design uses the STM32 Nucleo-L476RG development board to receive sensor feedback, calculate the required pump-speed command, and communicate with the other subsystems.

The overall project investigates whether variable speed circulation can reduce pump electrical consumption while maintaining acceptable thermal and hydraulic performance. The intended future application is the Lochinvar Regent Commercial Tankless Water Heater. Initial development and verification will occur using the required physical bench system rather than a direct connection to an operating Lochinvar boiler. The microcontroller will receive flow rate measurements, inlet and outlet water temperatures, and a representative heating demand signal. Flow and temperature feedback will allow the controller to evaluate the effect of changes in pump operation. Heating demand will provide an initial indication of the required operating condition. The control algorithm will calculate a preliminary pump speed command and adjust it according to the measured response. Before sending the command to the pump interface, the controller will enforce the selected speed limits and verify the applicable operating requirements.

The subsystem will also detect invalid measurements and abnormal operating conditions. When a fault occurs, the controller will execute the approved safe response and record the fault for later evaluation. The Microcontroller and Control Logic Subsystem will perform real time control. Subsystem 5 will be responsible for recording the measurements, performing Dymola simulation, and analyzing experimental performance. Both subsystems will use the same STM32 platform and must share the available peripherals without conflicting pin assignments.

#### 1. Sensor Acquisition and Validation

The STM32 will receive flow, temperature, and representative heating demand measurements from Subsystem 1. The flow sensor will use a pulse/frequency interface if supported by the final selected configuration. Inlet and outlet temperature measurements will be received from MAX31865 modules through SPI. Heating demand will be received through an analog input after the external 0–10 V signal has been conditioned to the STM32's permitted voltage range. Each measurement will be checked for validity before being used in the control algorithm.

#### 2. Control Algorithm
   
The controller will calculate an initial pump speed command based on heating demand and flow conditions. Outlet temperature feedback will then be used to determine whether the command requires adjustment. The algorithm will enforce the selected minimum and maximum pump commands. It will also check the measured flow against the approved minimum flow requirement. The exact controller gains, feedforward relationship, and operating thresholds will be finalized using Dymola simulation and physical bench results.

#### 3. Pump Command Interface

The STM32 will send the calculated speed command to the selected pump or drive through an electrically compatible interface. PWM is the preliminary command method. If the selected pump requires 0–10 V analog control, a suitable conversion or interface circuit will be required instead. The microcontroller will not directly supply motor power.

#### 4. Controller Monitoring and Fault Handling
The controller will monitor sensor validity, measured flow, temperature, and relevant operating states. If an abnormal condition is detected, the controller will record the fault and execute the approved response. Normal operation will resume only when the defined recovery conditions are satisfied.

3. The power requirements of the flow sensor and any necessary conditioning circuit.
4. The power and ground connections for both MAX31865 modules.
5. The power and ground connections for the microSD interface.
6. The separate mains power connections serving the pump and heat source.
7. Required electrical separation, protection, and grounding arrangements.

#### Sensor Feedback Connections

**Flow rate feedback:** The preliminary design assigns PA0 to a timer input capture function. If the selected flow sensor provides a compatible pulse signal, the controller will determine flow rate from the measured pulse frequency using the sensor's verified calibration relationship. If the selected output is analog instead, the interface and pin allocation will be revised. Inlet temperature feedback: The inlet PT100 RTD will connect to a MAX31865 interface module. The module will communicate with the STM32 over SPI1 using PB0 as its proposed chip select signal. Outlet temperature feedback: The outlet PT100 RTD will connect to a second MAX31865 module. The module will share the SPI1 clock and data lines but use PB1 as its proposed independent chip select signal.

**Heating demand feedback:** The representative 0–10 V signal will pass through an approved analog conditioning circuit before reaching the proposed PA1 ADC input. The final electrical design will show each sensor's power, ground, signal, and connector assignments.

### Build Procedure
--- 

**Step 1: Prepare the controller hardware.**
* Obtain the STM32 Nucleo-L476RG, compatible USB cable, temperature interface modules, sensor-conditioning components, and approved low voltage power equipment.

**Step 2: Configure the STM32 peripherals.**
* Create the STM32CubeIDE project and configure the proposed GPIO, ADC, SPI1, timer, PWM, and USART2 peripherals using STM32CubeMX.

**Step 3: Verify power connections.**
* Confirm the development board's power configuration, available 3.3 V supply capacity, external module voltage requirements, and grounding arrangement.

**Step 4: Connect the flow sensor interface.**
* Connect the selected flow sensor through its verified signal conditioning interface to the assigned STM32 input.

**Step 5: Connect the temperature interfaces.**
* Connect the inlet and outlet MAX31865 modules to the shared SPI1 bus. Assign independent chip select signals and verify that each module can be addressed separately.

**Step 6: Connect the heating-demand interface.**
* Connect the representative 0–10 V source through a verified conditioning circuit. Confirm that the resulting ADC voltage remains within the STM32's permitted limits.

**Step 7: Configure the pump-command output.**
* Set up the proposed timer PWM output. Verify the electrical signal and its compatibility with the selected pump or drive before enabling motor operation.

**Step 8: Implement the control algorithm.**
* Develop firmware for sensor validation, pump speed calculation, command limiting, operating state management, and fault detection.

**Step 9: Integrate the logging interfaces.**
* Configure the serial message format used by Subsystem 5 and coordinate access to the shared SPI bus.

**Step 10: Verify individual functions.**
* Test each sensor input, output command, communication interface, and controller state independently.

**Step 11: Integrate the physical bench.**
* Connect the controller to the approved pump, sensor, and hydraulic equipment after completing the required electrical and safety inspections.

**Step 12: Conduct controlled experiments.**
* Perform baseline and controlled trials using the approved test plan. Record flow, temperature, demand, pump commands, and fault information.

**Step 13: Complete subsystem verification.**
* Document controller performance, signal compatibility, timing, operating limit enforcement, and fault responses.

## Analysis

The Microcontroller and Control Logic Subsystem was analyzed to determine the electrical compatibility, measurement resolution, control requirements, and performance of the proposed variable speed circulation pump controller. The following calculations provide engineering justification for the selected STM32L476RG microcontroller, signal conditioning circuitry, sensor interfaces, and control algorithm.

### 1. Heating-Demand Signal Conditioning

The representative heating demand signal used during physical bench testing ranges from 0–10 V. Since the STM32L476RG operates with a nominal 3.3 V ADC reference, the incoming signal must be scaled before being connected to PA1.

The voltage divider equation is:

$$
V_{ADC}=V_{in}\left(\frac{R_2}{R_1+R_2}\right)
$$

Where:

* $V_{ADC}$ = conditioned voltage supplied to the ADC
* $V_{in}$ = representative heating demand input voltage
* $R_1$ = upper voltage divider resistance
* $R_2$ = lower voltage divider resistance

The proposed resistor values are:

$$
R_1=22\text{ k}\Omega
$$

$$
R_2=10\text{ k}\Omega
$$

Using the maximum specified input voltage of 10 V:

$$
V_{ADC,max}=10\left(\frac{10,000}{22,000+10,000}\right)
$$

$$
V_{ADC,max}=10(0.3125)
$$

$$
V_{ADC,max}=3.125\text{ V}
$$

The nominal voltage margin between the maximum conditioned signal and the ADC reference is:

$$
V_{margin}=V_{REF}-V_{ADC,max}
$$

$$
V_{margin}=3.3-3.125
$$

$$
V_{margin}=0.175\text{ V}
$$

The calculated maximum nominal voltage remains below the nominal ADC reference voltage. The final signal conditioning circuit must account for resistor tolerances, voltage transients, ADC sampling requirements, source impedance, and overvoltage protection.

The proposed voltage divider establishes the required nominal voltage scaling. Additional protection circuitry must be verified before hardware integration.

### 2. Analog-to-Digital Converter Resolution

The STM32L476RG ADC will be configured for 12-bit operation.

The total number of available conversion levels is:

$$
N=2^{12}
$$

$$
N=4096
$$

Using the nominal ADC reference voltage of 3.3 V, the theoretical voltage resolution is:

$$
V_{LSB}=\frac{V_{REF}}{2^{12}}
$$

$$
V_{LSB}=\frac{3.3}{4096}
$$

$$
V_{LSB}=0.0008057\text{ V}
$$

$$
V_{LSB}\approx0.806\text{ mV}
$$

The maximum digital ADC code is:

$$
ADC_{max}=2^{12}-1
$$

$$
ADC_{max}=4095
$$

The approximate ADC reading corresponding to the maximum nominal conditioned heating-demand voltage is:

$$
ADC_{raw,max}=\frac{V_{ADC,max}}{V_{REF}}(2^{12}-1)
$$

$$
ADC_{raw,max}=\frac{3.125}{3.3}(4095)
$$

$$
ADC_{raw,max}\approx3878
$$

The theoretical resolution referenced to the original heating demand input is:

$$
V_{in,LSB}=V_{LSB}\left(\frac{R_1+R_2}{R_2}\right)
$$

$$
V_{in,LSB}=0.806\left(\frac{22+10}{10}\right)
$$

$$
V_{in,LSB}\approx2.58\text{ mV}
$$

The theoretical measurement resolution supports the proposed heating demand acquisition requirements. Actual measurement accuracy will depend on calibration, electrical noise, component tolerances, and ADC reference accuracy.

### 3. Heating Demand Percentage Calculation

The STM32 converts the raw ADC measurement into the corresponding conditioned voltage using:

$$
V_{ADC}=\frac{ADC_{raw}}{4095}V_{REF}
$$

The original input voltage is reconstructed using the voltage divider ratio:

$$
V_{in}=V_{ADC}\left(\frac{R_1+R_2}{R_2}\right)
$$

The representative heating-demand percentage is calculated as:

$$
D=\frac{V_{in}}{V_{in,max}}\times100
$$

For the specified 0–10 V input range:

$$
D=\frac{V_{in}}{10}\times100
$$

Substituting the ADC conversion and voltage-divider equations:

$$
D=\frac{ADC_{raw}V_{REF}(R_1+R_2)}{4095R_2V_{in,max}}\times100
$$

Where:

* $D$ = representative heating-demand percentage
* $V_{in}$ = reconstructed input voltage
* $V_{in,max}$ = maximum specified input voltage
* $ADC_{raw}$ = measured ADC value
* $V_{REF}$ = ADC reference voltage
* $R_1$ = upper voltage-divider resistance
* $R_2$ = lower voltage-divider resistance

The valid heating demand range is:

$$
0\%\leq D\leq100\%
$$

The calculated heating-demand percentage will be used as an input to the feedforward control algorithm. Measurements outside the approved electrical input range will be evaluated by the input-validation and fault-detection functions.

### 4. Flow Sensor Measurement

The KEYENCE FD-Q50C flow sensor provides feedback regarding the measured water flow rate through the physical bench system.

PA0 is proposed as the flow sensor input using the TIM2_CH1 input capture peripheral, provided that the selected sensor configuration supports a compatible pulse output.

The timer counter frequency is calculated as:

$$
f_{counter}=\frac{f_{TIM2}}{PSC+1}
$$

The measured pulse period is:

$$
T_{pulse}=\frac{\Delta C}{f_{counter}}
$$

The corresponding pulse frequency is:

$$
f_{pulse}=\frac{1}{T_{pulse}}
$$

Substituting the timer measurement:

$$
f_{pulse}=\frac{f_{counter}}{\Delta C}
$$

Where:

* $f_{TIM2}$ = TIM2 input clock frequency
* $PSC$ = timer prescaler
* $f_{counter}$ = timer counter frequency
* $\Delta C$ = difference between consecutive captured timer counts, accounting for counter rollover
* $T_{pulse}$ = measured pulse period
* $f_{pulse}$ = measured pulse frequency

For a verified pulse frequency output with proportional scaling, the flow rate is calculated as:

$$
Q=\frac{f_{pulse}}{K_f}
$$

Where:

* $Q$ = measured water flow rate
* $K_f$ = sensor calibration factor expressed as frequency per unit flow rate

The final calibration factor and conversion equation will depend on the verified KEYENCE output configuration.

If a compatible pulse-frequency output is unavailable, the signal conditioning circuitry and STM32 peripheral configuration will be revised to accommodate the supported sensor output.

### 5. Temperature Measurement and Conversion

The inlet and outlet water temperatures will be measured using two PT100 RTDs connected to independent MAX31865 interface modules.

The MAX31865 modules communicate with the STM32 through the shared SPI1 communication bus.

| Signal | STM32 Pin | Function |
|---|---|---|
| SPI Clock | PA5 | Synchronizes SPI communication |
| SPI MISO | PA6 | Receives temperature measurement data |
| SPI MOSI | PA7 | Transmits configuration and register commands |
| Inlet Temperature Chip Select | PB0 | Selects inlet MAX31865 |
| Outlet Temperature Chip Select | PB1 | Selects outlet MAX31865 |

The MAX31865 provides a 15-bit digital measurement representing the ratio between the measured RTD resistance and the reference resistance.

The RTD resistance is calculated as:

$$
R_{RTD}=\frac{ADC_{RTD}}{32768}R_{REF}
$$

Where:

* $R_{RTD}$ = measured RTD resistance
* $ADC_{RTD}$ = 15-bit MAX31865 resistance measurement
* $R_{REF}$ = reference resistance of the selected MAX31865 module

For temperatures greater than or equal to 0 degrees Celsius, the PT100 resistance relationship is represented using the Callendar–Van Dusen equation:

$$
R(T)=R_0(1+AT+BT^2)
$$

Where:

* $R(T)$ = RTD resistance at temperature $T$
* $R_0$ = nominal RTD resistance at 0 degrees Celsius
* $A$ = first order temperature coefficient
* $B$ = second order temperature coefficient
* $T$ = temperature in degrees Celsius

The standard IEC 60751 PT100 coefficients are:

$$
R_0=100\ \Omega
$$

$$
A=3.9083\times10^{-3}\ ^\circ\text{C}^{-1}
$$

$$
B=-5.775\times10^{-7}\ ^\circ\text{C}^{-2}
$$

Rearranging the resistance equation:

$$
BT^2+AT+\left(1-\frac{R(T)}{R_0}\right)=0
$$

Solving for the applicable nonnegative temperature:

$$
T=\frac{-A+\sqrt{A^2-4B\left(1-\frac{R(T)}{R_0}\right)}}{2B}
$$

The measured temperature is converted into degrees Fahrenheit using:

$$
T_F=\frac{9}{5}T_C+32
$$

The temperature difference across the heating system is calculated as:

$$
\Delta T=T_{out}-T_{in}
$$

Where:

* $T_{out}$ = measured outlet water temperature
* $T_{in}$ = measured inlet water temperature
* $\Delta T$ = temperature rise across the heating system

The calculated temperature measurements will be used for thermal analysis, outlet temperature regulation, fault detection, and experimental data logging. The reference resistance, RTD wiring configuration, and calibration parameters will be verified against the selected hardware.

### 6. Thermal Energy Analysis

The thermal energy transfer rate to the water is expressed as:

$$
\dot{Q}_h=\dot{m}c_p\Delta T
$$

The mass flow rate is calculated as:

$$
\dot{m}=\rho Q_v
$$

Substituting the mass flow rate into the thermal energy equation:

$$
\dot{Q}_h=\rho Q_vc_p\Delta T
$$

Where:

* $\dot{Q}_h$ = thermal energy transfer rate
* $\dot{m}$ = mass flow rate
* $\rho$ = water density
* $Q_v$ = volumetric flow rate
* $c_p$ = specific heat capacity of water
* $\Delta T$ = temperature difference

For water flowing through a heating system, the approximate relationship in customary engineering units is:

$$
\dot{Q}_h\approx500Q\Delta T
$$

Where:

* $\dot{Q}_h$ = heating rate in BTU/hr
* $Q$ = water flow rate in GPM
* $\Delta T$ = temperature rise in degrees Fahrenheit

Rearranging the equation to determine the temperature rise:

$$
\Delta T\approx\frac{\dot{Q}_h}{500Q}
$$

Rearranging the equation to determine the required flow rate:

$$
Q\approx\frac{\dot{Q}_h}{500\Delta T}
$$

The required temperature rise is determined from the desired outlet temperature and measured inlet temperature:

$$
\Delta T_{required}=T_{setpoint}-T_{in}
$$

The estimated required flow rate under steady state heating conditions is:

$$
Q_{required}\approx\frac{\dot{Q}_h}{500(T_{setpoint}-T_{in})}
$$

This relationship applies when the desired outlet temperature exceeds the inlet temperature and the heating rate is positive.

The thermal relationship provides engineering justification for incorporating both flow rate and temperature feedback into the microcontroller control algorithm. The heating rate, flow rate, and temperature measurements used for experimental calculations will be obtained from the physical bench system.

### 7. Outlet Temperature Error

The microcontroller continuously compares the measured outlet temperature with the desired temperature setpoint.

The temperature error is calculated as:

$$
e(t)=T_{setpoint}-T_{out}(t)
$$

Where:

* $e(t)$ = temperature error
* $T_{setpoint}$ = desired outlet temperature
* $T_{out}(t)$ = measured outlet temperature

The absolute temperature error is:

$$
e_{absolute}(t)=|T_{setpoint}-T_{out}(t)|
$$

The required steady-state temperature tolerance is:

$$
|T_{setpoint}-T_{out}|\leq4^\circ\text{F}
$$

The lower acceptable temperature boundary is:

$$
T_{lower}=T_{setpoint}-4^\circ\text{F}
$$

The upper acceptable temperature boundary is:

$$
T_{upper}=T_{setpoint}+4^\circ\text{F}
$$

The acceptable steady state operating range is:

$$
T_{setpoint}-4^\circ\text{F}\leq T_{out}\leq T_{setpoint}+4^\circ\text{F}
$$

The approved operating setpoint will be established using the physical bench equipment requirements. The specified temperature tolerance represents a performance requirement and is independent of the maximum safe operating temperature established by the equipment manufacturer.

### 8. Feedforward Control Analysis

The feedforward controller establishes an initial pump command based on the measured flow rate, inlet temperature, and representative heating demand.

The general feedforward relationship is:

$$
u_{ff}=F(Q,D,T_{in})
$$

Where:

* $u_{ff}$ = initial feedforward pump command
* $Q$ = measured water flow rate
* $D$ = representative heating-demand percentage
* $T_{in}$ = measured inlet temperature
* $F$ = feedforward control function

The feedforward control function will be developed using the selected pump characteristics, Dymola simulation results, and physical bench measurements.

The calculated feedforward command must remain within the approved pump operating range:

$$
u_{min}\leq u_{ff}\leq u_{max}
$$

Dymola simulation will provide preliminary controller parameters and operating conditions as inputs to the physical bench test. The final feedforward control function will be established through simulation and experimental characterization rather than assuming a linear relationship between heating demand and pump speed.

### 9. Proportional Integral Feedback Control

A proportional-integral (PI) feedback controller is proposed to adjust the pump command based on the measured outlet temperature error.

The continuous time PI control equation is:

$$
u_{fb}(t)=K_pe(t)+K_i\int_0^t e(\tau)\,d\tau
$$

Where:

* $u_{fb}(t)$ = feedback correction
* $K_p$ = proportional gain
* $K_i$ = integral gain
* $e(t)$ = measured temperature error

The discrete time implementation used by the STM32 is represented as:

$$
e[k]=T_{setpoint}-T_{out}[k]
$$

$$
I[k]=I[k-1]+e[k]T_s
$$

$$
u_{fb}[k]=K_pe[k]+K_iI[k]
$$

Where:

* $k$ = current control loop iteration
* $T_s$ = control loop sampling interval
* $I[k]$ = accumulated integral error
* $e[k]$ = temperature error at the current iteration

The preliminary control loop sampling interval is:

$$
T_s=100\text{ ms}
$$

$$
T_s=0.1\text{ s}
$$

The corresponding preliminary control loop frequency is:

$$
f_s=\frac{1}{T_s}
$$

$$
f_s=\frac{1}{0.1}
$$

$$
f_s=10\text{ Hz}
$$

The final control loop frequency and controller gains will be determined through simulation and physical bench testing. The sign of the controller gains must account for the relationship between pump speed, water flow, and outlet temperature. Integral anti windup will be implemented to prevent excessive accumulation of the integral term when the pump command reaches its operating limits.

### 10. Combined Pump Command

The calculated pump command combines the feedforward command and the feedback correction.

$$
u_{raw}[k]=u_{ff}[k]+u_{fb}[k]
$$

Substituting the discrete PI control equation:

$$
u_{raw}[k]=u_{ff}[k]+K_pe[k]+K_iI[k]
$$

The calculated command is restricted to the approved pump operating range using:

$$
u_{limited}[k]=\min\left(u_{max},\max\left(u_{min},u_{raw}[k]\right)\right)
$$

The equivalent piecewise representation is:

$$
u_{limited}[k]=
\begin{cases}
u_{min}, & u_{raw}[k]<u_{min}\\
u_{raw}[k], & u_{min}\leq u_{raw}[k]\leq u_{max}\\
u_{max}, & u_{raw}[k]>u_{max}
\end{cases}
$$

Where:

* $u_{raw}[k]$ = calculated pump command
* $u_{limited}[k]$ = restricted pump command
* $u_{min}$ = minimum approved pump command
* $u_{max}$ = maximum approved pump command

The command limitation prevents the controller from requesting operation outside the approved pump operating range.

The final pump command will also be evaluated against minimum flow requirements and safety conditions before being transmitted to Subsystem 3.

### 11. Minimum Flow Enforcement

The controller must maintain the minimum water flow required by the selected bench equipment.

The minimum-flow requirement is:

$$
Q_{measured}\geq Q_{min}
$$

The available flow margin is calculated as:

$$
Q_{margin}=Q_{measured}-Q_{min}
$$

The minimum-flow requirement is satisfied when:

$$
Q_{margin}\geq0
$$

An insufficient-flow condition exists when:

$$
Q_{margin}<0
$$

The flow deficit is calculated as:

$$
Q_{deficit}=\max(0,Q_{min}-Q_{measured})
$$

Where:

* $Q_{measured}$ = measured water flow rate
* $Q_{min}$ = minimum approved water flow rate
* $Q_{margin}$ = available flow margin
* $Q_{deficit}$ = amount of flow below the approved minimum

If insufficient flow is detected, the controller will prioritize restoring required circulation rather than reducing electrical power consumption. If the required circulation cannot be restored, the controller will initiate the approved protective response while preserving independent equipment safety protections. The minimum allowable flow rate will be established using the selected pump, heat source, and physical bench equipment requirements.

### 12. PWM Pump Control Analysis

PA8 is proposed as the pump command output using the TIM1_CH1 peripheral, provided that the selected circulation pump supports a compatible PWM interface.

The PWM duty cycle is calculated as:

$$
D_{PWM}=\frac{T_{ON}}{T_{period}}\times100
$$

Where:

* $D_{PWM}$ = PWM duty cycle in percent
* $T_{ON}$ = active signal duration
* $T_{period}$ = total PWM signal period

The PWM frequency is calculated as:

$$
f_{PWM}=\frac{1}{T_{period}}
$$

For edge aligned PWM, the STM32 timer frequency relationship is:

$$
f_{PWM}=\frac{f_{TIM1}}{(PSC+1)(ARR+1)}
$$

Rearranging to determine the required auto reload register value:

$$
ARR=\frac{f_{TIM1}}{f_{PWM}(PSC+1)}-1
$$

Where:

* $f_{TIM1}$ = TIM1 input clock frequency
* $PSC$ = timer prescaler
* $ARR$ = auto reload register value

For conventional edge aligned, active high PWM operation, the duty cycle is represented as:

$$
D_{PWM}=\frac{CCR}{ARR+1}\times100
$$

The corresponding capture/compare register value is:

$$
CCR=\frac{D_{PWM}}{100}(ARR+1)
$$

Where:

* $CCR$ = timer capture/compare register value

The register values must be configured using valid integer values supported by the selected timer. The required PWM frequency, polarity, voltage level, and duty cycle limits will be established from the final pump manufacturer's documentation. The PWM duty cycle will not be assumed to equal the actual pump rotational speed percentage. The relationship between the command signal and pump operation will be verified experimentally.

### 13. Pump Affinity Law Analysis

The pump affinity laws describe the theoretical relationship between rotational speed, flow rate, developed head, and mechanical power under applicable operating conditions.

The relationship between pump speed and flow rate is:

$$
\frac{Q_2}{Q_1}=\frac{N_2}{N_1}
$$

The relationship between pump speed and developed head is:

$$
\frac{H_2}{H_1}=\left(\frac{N_2}{N_1}\right)^2
$$

The relationship between pump speed and mechanical power is:

$$
\frac{P_2}{P_1}=\left(\frac{N_2}{N_1}\right)^3
$$

Where:

* $Q_1$ = baseline flow rate
* $Q_2$ = controlled flow rate
* $H_1$ = baseline developed head
* $H_2$ = controlled developed head
* $N_1$ = baseline pump rotational speed
* $N_2$ = controlled pump rotational speed
* $P_1$ = baseline mechanical power
* $P_2$ = controlled mechanical power

Rearranging the affinity laws:

$$
Q_2=Q_1\left(\frac{N_2}{N_1}\right)
$$

$$
H_2=H_1\left(\frac{N_2}{N_1}\right)^2
$$

$$
P_2=P_1\left(\frac{N_2}{N_1}\right)^3
$$

The theoretical mechanical power reduction is calculated as:

$$
P_{reduction}=\frac{P_1-P_2}{P_1}\times100
$$

Substituting the mechanical power affinity relationship:

$$
P_{reduction}=\left[1-\left(\frac{N_2}{N_1}\right)^3\right]\times100
$$

The affinity laws provide theoretical justification for reducing pump rotational speed when the required thermal and hydraulic operating conditions permit. These relationships apply under appropriate similarity conditions and do not directly establish measured electrical power savings. Actual pump performance and electrical power consumption will be determined through physical bench testing.

### 14. Hydraulic and Electrical Power Analysis

The hydraulic power transferred to the circulating water is calculated as:

$$
P_{hydraulic}=\rho gQ_vH
$$

Where:

* $P_{hydraulic}$ = hydraulic power in watts
* $\rho$ = water density in kilograms per cubic meter
* $g$ = gravitational acceleration in meters per second squared
* $Q_v$ = volumetric flow rate in cubic meters per second
* $H$ = developed pump head in meters

The relationship between pressure differential and developed pump head is:

$$
H=\frac{\Delta p}{\rho g}
$$

Substituting the pressure relationship:

$$
P_{hydraulic}=Q_v\Delta p
$$

The mechanical shaft power required by the pump is:

$$
P_{shaft}=\frac{P_{hydraulic}}{\eta_{pump}}
$$

The corresponding electrical input power is represented as:

$$
P_{electrical}=\frac{P_{shaft}}{\eta_{motor}\eta_{drive}}
$$

Combining the power relationships:

$$
P_{electrical}=\frac{\rho gQ_vH}{\eta_{pump}\eta_{motor}\eta_{drive}}
$$

Where:

* $\eta_{pump}$ = hydraulic pump efficiency
* $\eta_{motor}$ = motor efficiency
* $\eta_{drive}$ = motor-drive efficiency, where applicable

The efficiencies depend on the selected pump and its operating conditions. Therefore, actual electrical power consumption cannot be determined solely from the pump affinity laws. Electrical input power will be measured directly using the performance-monitoring equipment associated with Subsystem 4.

### 15. Electrical Power Savings

The actual electrical power savings will be determined by comparing measured electrical input power during baseline and variable speed operation under matched test conditions.

The average baseline electrical input power is:

$$
\overline{P}_{baseline}=\frac{1}{T}\int_0^T P_{baseline}(t)\,dt
$$

The average controlled electrical input power is:

$$
\overline{P}_{controlled}=\frac{1}{T}\int_0^T P_{controlled}(t)\,dt
$$

For uniformly sampled measurements, the average baseline power is:

$$
\overline{P}_{baseline}=\frac{1}{n}\sum_{i=1}^{n}P_{baseline,i}
$$

The average controlled power is:

$$
\overline{P}_{controlled}=\frac{1}{n}\sum_{i=1}^{n}P_{controlled,i}
$$

The percentage of electrical power savings is:

$$
P_{savings}=\frac{\overline{P}_{baseline}-\overline{P}_{controlled}}{\overline{P}_{baseline}}\times100
$$

Where:

* $\overline{P}_{baseline}$ = average measured baseline electrical input power
* $\overline{P}_{controlled}$ = average measured variable speed electrical input power
* $P_{savings}$ = measured electrical power savings percentage
* $n$ = number of uniformly sampled measurements
* $T$ = measurement duration

The project performance target is:

$$
P_{savings}\geq10\%
$$

Rearranging the power savings equation establishes the maximum allowable controlled power consumption required to meet the project target:

$$
\overline{P}_{controlled}\leq\overline{P}_{baseline}(1-0.10)
$$

$$
\overline{P}_{controlled}\leq0.90\overline{P}_{baseline}
$$

The controller must achieve the power savings target while maintaining the required outlet temperature tolerance and minimum flow requirements.

### 16. Electrical Energy Consumption

Electrical energy consumption is determined by integrating measured electrical input power over the test duration.

The baseline electrical energy consumption is:

$$
E_{baseline}=\int_0^T P_{baseline}(t)\,dt
$$

The controlled electrical energy consumption is:

$$
E_{controlled}=\int_0^T P_{controlled}(t)\,dt
$$

For uniformly sampled measurements, electrical energy consumption can be approximated as:

$$
E_{baseline}\approx\sum_{i=1}^{n}P_{baseline,i}\Delta t
$$

$$
E_{controlled}\approx\sum_{i=1}^{n}P_{controlled,i}\Delta t
$$

Where:

* $E_{baseline}$ = baseline electrical energy consumption
* $E_{controlled}$ = controlled electrical energy consumption
* $\Delta t$ = measurement sampling interval
* $n$ = number of measurement intervals

When power is measured in watts and time is measured in seconds, the resulting energy is expressed in joules.

Conversion from joules to kilowatt-hours is calculated as:

$$
E_{kWh}=\frac{E_J}{3.6\times10^6}
$$

The electrical energy savings percentage is:

$$
E_{savings}=\frac{E_{baseline}-E_{controlled}}{E_{baseline}}\times100
$$

Energy consumption will be evaluated over comparable test cycles to determine the overall effectiveness of the variable speed control algorithm.

### 17. Control and Data Logging Timing

The microcontroller control loop and data logging operations will execute at separate intervals.

The preliminary control loop interval is:

$$
T_{control}=0.1\text{ s}
$$

The maximum data logging interval is:

$$
T_{logging,max}=1\text{ s}
$$

The corresponding preliminary control loop frequency is:

$$
f_{control}=\frac{1}{T_{control}}
$$

$$
f_{control}=\frac{1}{0.1}
$$

$$
f_{control}=10\text{ Hz}
$$

The minimum data logging frequency is:

$$
f_{logging,min}=\frac{1}{T_{logging,max}}
$$

$$
f_{logging,min}=\frac{1}{1}
$$

$$
f_{logging,min}=1\text{ Hz}
$$

The number of control loop iterations occurring between logging events at the proposed control interval and maximum logging interval is:

$$
N=\frac{T_{logging,max}}{T_{control}}
$$

$$
N=\frac{1}{0.1}
$$

$$
N=10
$$

The firmware execution time must remain within the selected control loop interval:

$$
T_{execution}\leq T_{control}
$$

The total control loop execution time includes:

$$
T_{execution}=T_{acquisition}+T_{processing}+T_{control,calc}+T_{output}+T_{safety}+T_{overhead}
$$

Where:

* $T_{acquisition}$ = sensor acquisition time
* $T_{processing}$ = signal conversion and validation time
* $T_{control,calc}$ = control algorithm calculation time
* $T_{output}$ = pump command update time
* $T_{safety}$ = safety evaluation time
* $T_{overhead}$ = additional scheduling and communication overhead

The firmware will be structured to prevent UART communication and microSD storage operations from introducing unacceptable delays into the control loop.

### 18. Simulation and Experimental Validation

The Dymola simulation will be used to establish preliminary controller parameters, expected system responses, and operating conditions before physical bench testing. The physical bench test is a required component of the project and will provide measured experimental data for validating the controller and simulation model.

The absolute difference between a simulated and measured value is calculated as:

$$
E_{absolute}=|X_{simulated}-X_{measured}|
$$

For nonzero measured reference values, the percentage error is calculated as:

$$
E_{percent}=\frac{|X_{simulated}-X_{measured}|}{|X_{measured}|}\times100
$$

Where:

* $X_{simulated}$ = predicted simulation value
* $X_{measured}$ = experimentally measured value
* $E_{absolute}$ = absolute model error
* $E_{percent}$ = percentage model error

The mean absolute error is calculated as:

$$
MAE=\frac{1}{n}\sum_{i=1}^{n}|X_{simulated,i}-X_{measured,i}|
$$

The root mean square error is calculated as:

$$
RMSE=\sqrt{\frac{1}{n}\sum_{i=1}^{n}(X_{simulated,i}-X_{measured,i})^2}
$$

Where:

* $n$ = number of matched data points
* $X_{simulated,i}$ = simulated value at data point $i$
* $X_{measured,i}$ = measured value at data point $i$

Simulation and experimental measurements must be compared under equivalent operating conditions and aligned measurement intervals. The calculated errors will be used to evaluate the accuracy of the simulation and identify necessary improvements to the control algorithm. The experimental data and simulation results will be processed through Subsystem 5.

### 19. Experimental Repeatability and Uncertainty

Repeated physical bench tests will be performed to evaluate controller performance and experimental repeatability.

The mean measured value is calculated as:

$$
\overline{X}=\frac{1}{n}\sum_{i=1}^{n}X_i
$$

The sample standard deviation is calculated as:

$$
s=\sqrt{\frac{\sum_{i=1}^{n}(X_i-\overline{X})^2}{n-1}}
$$

The standard uncertainty associated with the sample mean is:

$$
u_{\overline{X}}=\frac{s}{\sqrt{n}}
$$

For independent uncertainty contributions, the combined standard uncertainty is calculated as:

$$
u_c=\sqrt{u_1^2+u_2^2+\cdots+u_m^2}
$$

The 95 percent confidence interval for the mean of independent repeated measurements, assuming approximately normally distributed results, is calculated as:

$$
CI_{95\%}=\overline{X}\pm t_{0.975,n-1}\frac{s}{\sqrt{n}}
$$

Where:

* $\overline{X}$ = mean measured value
* $X_i$ = individual measured value
* $n$ = number of repeated measurements
* $s$ = sample standard deviation
* $u_{\overline{X}}$ = standard uncertainty of the sample mean
* $u_c$ = combined standard uncertainty
* $u_1,u_2,\ldots,u_m$ = independent uncertainty contributions
* $t_{0.975,n-1}$ = Student's t-distribution critical value

Baseline and variable speed measurements will be collected under matched operating conditions. The calculated uncertainty and confidence intervals will be used to evaluate the consistency of the measured electrical power savings, temperature regulation, and flow-rate performance.

## Conclusion

The Microcontroller and Control Logic Subsystem will provide the processing and control functions required for the Variable Speed Circulation Pump Controller. The preliminary design uses the STM32 Nucleo-L476RG to receive flow, temperature, and representative heating demand measurements, calculate pump-speed commands, and enforce approved operating limits.

The detailed electrical design identifies proposed STM32 pins for the sensor inputs, temperature interfaces, pump command, serial communication, and shared microSD connection. It also establishes the need for verified power distribution, signal conditioning, and electrical separation between low voltage control circuits and mains powered equipment. The controller will be integrated with the required physical bench to evaluate its performance under baseline and variable speed operating conditions. Dymola simulation will provide preliminary controller settings, while measured bench results will be used to verify the final control behavior.

Before construction, the remaining design decisions include confirming the selected pump interface, flow-sensor output, signal conditioning components, STM32 pin assignments, and equipment specific operating limits. These details will be incorporated into the final buildable schematic and verified during subsystem testing. The completed subsystem will support safe and repeatable pump speed control and provide the operating information needed by the Data Logging and Simulation Subsystem to evaluate electrical savings, thermal stability, and overall controller performance.
